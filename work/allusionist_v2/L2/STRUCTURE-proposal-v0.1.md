# 小説の構造とエンティティ構造の試案（v0.1 — 探索に基づく提案）

対象: 『幻想再帰のアリュージョニスト』（カクヨム 本編 589 話）＋作者の関連作品
（ハニーウィッチ・ユーフォリア 等、原文 corpus に存在する別作品群）。
本案は「統合＝1 实体に潰す」をやめ、**名義の系譜（来歴）と作品間の想起（質感）を
保存する構造**への転換を提案する。用語は「カクヨムの話番号（chNNNN）」「になろうの
章番号」で書き分け、"章/話" の混用は使わない。

## 1. 観測された構造（事実）

- 本編は「0-x（序）・1-x（第1章群）…」の**話番号体系**で進行し、になろう側は
  章（ch）として同一内容を章単位で保持（chapter-map: 章 → 話リスト）。
  現状 になろう側は最新 第5章（= 章は語りの単位、話は投稿の単位）。
- 語り手「俺」は作品ごとに**別人物**（ch00001 の「俺」= 転生保険の殺し屋、
  本編の「俺」= アキラ）。テキスト中に名前を持たない narrator entity が存在する。
- 別名・変名は**物語内で生成される**（呼称宣言・名乗り・通称）。同一人物でも
  場面・時期・作品で「質感」が違う（ユディーア = エレクトラ/キニス、
  同一の存在だが語られる情報が異なる）。
- v2〜v4 の統合は統計（頻出・共起）主体で、質感・来歴を失わせた
  （アズ→アズーリア型の略称代表名、自己愛/紫型の一般語实体、
  作品跨ぎ統合の混入）。

## 2. エンティティ構造の試案

### 2.1 単位
- **Entity = 「語られた個体」の単位**（人・存在・制度・場所・用語）。
  統合の単位は「人間としての同一性」ではなく「語りの個体」にする。
- **IdentityLink（同一性リンク）**: 同一の存在だが質感・時期・作品が異なる
  情報系列を**別实体のまま結ぶ**（ユディーア ↔ キニス ↔ エレクトラ）。
  集約・統合（1 实体化）は行わない。閲覧・検索時に相互想起でつなぐ。
- **NameLineage（名義系譜）**: 名義 → 实体 の対応を**来歴エッジ**として持つ
  （chNNNN で名乗り/呼称宣言で生成されたことを引用付きで記録）。
  略称・愛称・変名・転生名は独立ノードのまま親へぶら下がる（代表名による
  一本化を要求しない。primary 概念は「その系列で最も正式に名乗られた名」に
    限定し、置換の強制はしない）。
- **Narrator（語り手）**: 作品単位の独立 entity（「俺」「語り手」）。本編
  narrator → 本編主人公への link は本文証拠でのみ貼る。
- **Aspect（側面）**: 親实体の側面（容姿、正体、成長段階）は parent/children
  で維持（現行方針を踏襲）。

### 2.2 証拠の階（ページとして公開）
- **chNNNN 統合記録ページ**（話ごと 1 ページ）: その話で観測された名義、
  採用された同一性判定（explicit 呼称宣言・強推論）と**使用した情報**
  （引用 ¶、台帳抜粋、その話の要約）、および**検索・想起された関連 ch**
  （その登場人物の過去の登場話リスト）。
- **Entity 統合記録ページ**（实体ごと 1 ページ）: その实体に至る全判定の
  履歴（いつどの話のどの証拠で統合/分離/維持されたか）、IdentityLink 群、
  名義系譜ツリー。→ 現在の「監査表」を発展させた形。
- 両ページは相互参照（話ページ ↔ 实体ページ）。来歴チェーン
  （run → 話ページ → 判定エッジ → 原文引用 ¶N）を切らない。

### 2.3 逐次解析の在り方（v5 運用）
1. 話 chNNNN を読む前に、その話に出現しうる名義の**関連 ch を検索**
   （名義系譜 index から過去の登場話を取得）し、想起コンテキストとして注入。
2. 実読で得た判定（explicit/strong/separation）を**話ページに記録**。
3. 实体ページ側へ集約（append-only の判定ログとして）。
4. 統合の適用は explicit 证据 + 全出現話の読了を要求（恒久基準）。
   作品跨ぎの同一性は統合せず IdentityLink（相互想起）として保存。

### 2.4 移行手順
1. 既存 805 適用 pair を「同一性リンク」へ降格変換（1 实体化を解除）:
   alias ノードを独立实体に戻し、代表名实体との link のみ残す。
   （バナー・置換の強制 → 相互想起表示へ変更）
2. 一般語・場面名の实体（自己愛/紫型）は entity_status で識別し、
   実体性のないものを準实体へ格下げ（ページは残す）。
3. 作品跨ぎ pair を機械検出（作品別出現分布）→ IdentityLink 候補として表示。
4. 逐次実読 v5 はこの構造の上に走り、判定をページとして記録する。

## 3. 未決・論点
- 「同一人物だが質感が違う」の粒度境界（ユディーア/キニス level = 作品単位か、
  場面単位か）→ 実読ログで粒度を確定する。
- 準实体（概念・比喩が語られる場）の扱い: 实体ページを残すか索引に寄せるか。
- primary 概念の廃止範囲（导航の代表表記はどう選ぶか = 系譜の「正式名乗り」優先、
  なければ最多出現を**表示上**の代表とする）。
