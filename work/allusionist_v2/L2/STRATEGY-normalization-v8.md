  6. 実行中に精度検証のゲートが無かった（バッチ→全量適用→公開一直線）。

## 1. 正しい正規化仕様（v8 規範）
### 1.1 入層（名義候補の定義）
- 登録は「単独で呼称として使える名」のみ。対象外: 一般名詞（アバター/王/霊媒/幼馴染/お姫様/少女/動物種名…）、観測ラベル（`X（Y）`括弧注記・スラッシュ複合・? 付き）、名詞句（「世界そのものに対して浸食を行う寄生異獣」「まことの名」）、原文 0 使用面。
- 括弧注記は入層前に分解する: 表層 `A（B）` → A と B を別面として審査（A が一般語なら B のみ候補）。furigana・《》・《全角》表記は表記ゆれとして本体名に寄せる。
- 一般呼称（俺・彼・彼女…）は恒久基準どおり L2 対象外（work 層照応解決）。

### 1.2 証拠階層（原文のみを証拠とする）
- T1 宣名: 「名はX」「私の名は『X』」「宣名」「その名はX」「まことの名をX」＋引用逐語照合。
- T2 同一性述語: 「XはYである」「X、すなわちY」「YことX」「YであるX」で主語が個体であるもの。
- T3 表記ゆれ: 中点/全半角/括弧furigana/旧字体/読み仮名（機械判定・要検証不要）。
- T4 強い照応（同一場面連続・自己照応）→ **統合せず要検証**（identity-links-strong に分離）。
- 禁止: 地の文の定義文（「AとはBを意味する」）、比喩同格、種紹介（「古代文字（ジャッフハリマータ）の呪文」型の語説明星）、記述一致の照応推論、「AではなくB」= 分離証拠。
- 統合の適用は **T1∨T2∨T3 逐語照合済み**のみ。

### 1.3 受け取り側（統合先）整合
- alias の参照クラス（人/技・呪文/動物/集団/場所/守護者-器）と統合先实体のクラスが異なる辺は適用しない。統合先の実体同一性を先に確定してから alias を流す。
- 群内辺は辺単位適用（DSU 推移閉包禁止）。A=B 辺と B=C 辺の両方が T1/T2 を個別に通ったときだけ連結。

### 1.4 primary（代表名）規定
- primary = 本人宣名が明示された名（宣名引用付き）。宣名が無い实体は、敬称 suffix（くん/殿/さん/ちゃん）と上位語の部分文字列を除外した最多表記。
- 敬称形・短縮形（アズ、ハル）は正式形の alias。同一文共起で別人・同一性述語で同一（mech v3 区別は維持）。

### 1.5 無根拠の扱い
- 根拠引用のない旧統合は keep しない。**unmerged 審査キュー**（candidates/review）へ降ろし、統合台帳には載せない。「反例なし」は維持根拠ではない。
