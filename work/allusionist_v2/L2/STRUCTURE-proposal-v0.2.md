# 構造試案 v0.2 — 一般呼称の work 層解決 / work 統合ページ・自由ページ層 / 同一名複数人物

v0.1 への追指 3 点（一般呼称、実施場所、同一名義）を反映した版。

## 1. 一般的すぎる呼称（俺・彼・彼女・二人…）

- **L2（正規化）では扱わない**。一般呼称は L2 实体台帳の統合対象から外す。
- 解決は **work 層（L0/L1 側）まで遡って**行う:
  - `narrators.json`（work 層データ）: 作品ごとの語り手 entity を定義する。
    語り手の特定は「明白なものだけ」— 自己紹介・作中名乗り・一人称と固有名の
    直結が本文に存在する章でのみ確立し、引用 ¶ を root にする。
  - 照応（照応解決）: 章単位の「彼/彼女/あいつ/二人」→ 直近の固有名实体への
    参照解決を **work 統合ページ（章ページ）の構造化セクション**として記録する。
    固有名が文脈に存在しない照応は unresolved のまま残す（推測で埋めない）。
- L2 正規化 wiki はこの work 層解決を**参照**するだけ（表示側で「俺→narrator
  参照リンク」を出す）。

## 2. 実装の場: work 層・work 統合ページ・自由ページ層

エンティティ正規化という仕事そのものは **work repo 側**で実施し、ページ層を持つ。

```
work/allusionist_v2/L2/
  pages/
    chapters/<chNNNN>.md     # work 統合ページ（章ごと）: 観測名義・判定・
                             # 使用した情報（引用¶）・その登場人物の関連ch想起・
                             # 照応解決（彼/彼女→实体）構造化セクション
    entities/<entity_id>.md  # 实体統合ページ: 判定履歴（ch→証拠→統合/分離/維持）・
                             # IdentityLink・名義系譜・同一名称 collision 情報
    free/<slug>.md           # 自由ページ層: 生成物が語る自由記述の場
                             # （仮説・考察・系譜解説。追記専用・来歴リンク必須）
  data/                      # narrator解決・照応解決・collision 判定の構造化データ
  runs/<run_id>/             # （変更なし）台帳・監査 run
```

- 章ページ・实体ページは work 層の一次記録（append-only）。LLM 生成部分は
  evidence/判定のみ、自由ページ層に narrative 考察を分離する。
- L2Wiki（表示側）は pages/ を**参照する公開ビュー**に留める
  （台帳→生成規則→正規化 wiki は不変、ページ層を L2 の一要素として接続）。

## 3. 同一名義の別人物（カーイン型）への対策

同一の名称が複数の人物（語りの個体）を指しうるケースの対策:

- **Entity key = 名称 + 人物系列**: entity id に disambiguator を持たせる
  （`E_char_カーイン__S1/S2`）。名称ノードは 1:N を前提とし、
  alias→实体 の単一対応を仕様上で禁止する（名称衝突は正常な入力）。
- 人物系列の分離根拠（機械検出 → 実読確認）:
  1. 同一章内で同名が**複数名として同時言及**される
     （「カーインとカーイン」「片方のカーイン」「元カーイン」「ロウ・カーイン」等、
     並列言及・区接頭辞）→ 機械スキャンで章レベル collision candidates。
  2. 同一 paragraph に同一名称 ×2 以上。
  3. 物語系譜の連続性（時系列・共演関係・語り手の言及）で群を分離 —
     実読バッチの mentions.role が群の系列証拠になる。
- 分離した群の名称表示: 区別接頭辞（ロウ・カーイン型）が本文にあれば
  それを表示名に、なければ `カーイン#2（第二のカーイン）` 型の注記表示。
- 統合（1 实体化）は「同一人物である章の明示」があった場合のみ、その章引用付き。
  迷う場合は常に分離＋相互参照（＝別人物の可能性があるなら分けて扱う）。

## 4. 実装順

1. data/narrators.json 生成（本編 narrator: 「俺」= アキラ の確立は名乗り章を特定）
2. 章ページの照応解決セクション（chNNNN 実読ログに連動して生成）
3. 同一名 collision 機械スキャン（全作品）→ collision レポート（ページ生成）
4. entities/ 統合ページ生成器（実読バッチ判定の蓄積から）
5. free/ 層の運用開始（initial: 本編構造の考察ページ）
